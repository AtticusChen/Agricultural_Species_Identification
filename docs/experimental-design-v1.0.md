# 薇甘菊地面目标检测实验设计 v1.0

日期：2026-08-04  
状态：可执行方案；正式对比实验需通过数据质控门  
适用数据：`mikania_detection_v1` 及其质控后的后续版本

## 1. 核心结论

本阶段只研究**地面 RGB 图像中的薇甘菊单类目标检测**：输入一张手机照片，输出薇甘菊株丛的边界框和置信度。无人机图像因目前没有斑块掩膜，暂不混入本轮训练；后续作为独立的语义分割子项目。

现有数据足以启动数据加载验证和基线训练，但还不适合直接宣称“低误报”或“跨地点泛化”。正式实验必须先完成三个质控任务：复核 16 个超大框、处理 12 张缺标签图、确认 123 张相似植物/背景候选是否真的不含薇甘菊。

本项目的研究主线调整为：

> 在严格按采集组隔离的条件下，通过物种分层的困难负样本训练和错误区域挖掘，降低复杂混生植被中的薇甘菊误报，同时保持目标召回率和部署速度。

候选方法暂命名为 **Mikania-HN**。形态属性辅助头暂不进入第一轮主实验，因为当前没有叶形、花簇、攀援状态等属性标签。

## 3. 研究问题与可证伪假设

### RQ1：基础可行性

使用 COCO 预训练的现代检测器，能否在按采集组隔离的内部测试集上稳定定位薇甘菊？

- H1：YOLO26s-640 能形成可复现的强实时基线。
- 否证条件：不同种子差异很大，或仅在训练/验证图像上有效、在内部测试集明显失效。

### RQ2：困难负样本

加入经确认的近似植物负样本，能否在召回率基本不下降的情况下减少误报？

- H2：物种分层采样优于简单地把所有负样本混入训练集。
- H3：基于基线模型误报区域的困难负样本挖掘，优于随机负样本训练。
- 否证条件：负样本方法在 3 个随机种子上方向不一致，或召回下降超过 2 个百分点而误报没有显著下降。

### RQ3：输入分辨率

在当前以中大型目标为主的数据上，960 输入是否仍能带来足以抵消延迟增加的精度收益？

- H4：960 可能改善少量较小目标，但总体收益有限。
- 否证/接受规则：若 mAP@0.5:0.95 提升不足 1 个百分点且延迟增加超过 30%，后续固定使用 640。

### RQ4：时间迁移

模型在 2025 年数据上训练后，能否迁移到 2026 年 3 月图像？

- H5：时间外性能会低于内部测试，但困难负样本训练不应明显损害时间外正样本召回。
- 限制：当前时间外测试只有 5 个划分单元且全为同一手机型号，因此结果只作“时间迁移”证据，不能写成“跨地区泛化”。

## 4. 数据版本与质控门

### D1：`mikania_detection_v1-pos`

即当前 462 张已标注正样本数据。用途仅限：数据加载验证、训练脚本烟雾测试、正样本基线预实验。

远程训练实际读取 `mikania_detection_v1_0_1`：它与 D1 的图片、标签、划分和目标框完全相同，只对 152 张缺少标准 JPEG 结束标记的文件副本无损追加 `FFD9`，并记录修复前后 SHA-256。该派生版本不属于数据增强或标签变化。

### D2：`mikania_detection_v1.1-qc`

在现有划分基础上完成以下处理后冻结：

1. 逐张复核 16 个超大框；合理近拍保留，框入明显非目标区域则重画。
2. 为 10 张明显正样本补框；2 张复杂混生图由能识别薇甘菊的人标记为“正样本、负样本或不确定”。
3. 新增图片必须跟随已有 `group_id` 进入同一集合，不能重新随机打散当前划分。
4. 记录每次标签修改的图片名、原标签、新标签、修改原因和复核人。

### D3：`mikania_detection_v1.2-hn`

对 123 张候选图只做一个简单判断：`无薇甘菊`、`含薇甘菊`、`不确定`。

- `无薇甘菊`：生成空 YOLO 标签，可进入困难负样本池。
- `含薇甘菊`：补画检测框，按采集组加入正样本集合。
- `不确定`：隔离，不进入训练、验证和测试。

确认后的负样本按“采集组 + 近重复簇 + 原物种文件夹”分层划分。目标比例为训练 70%、验证 15%、困难负样本测试 15%；小类别无法同时覆盖三份时，优先保证测试可解释性，并在报告中列出每个物种的真实数量。正样本现有划分保持不动。

### D4：未来地理外部测试集

论文若要主张跨地点泛化，需要另采集至少 3 个未参与训练的新地点。建议每地点不少于 40 张薇甘菊正样本和 40 张近似植物/背景负样本，总计至少 240 张；该集合从采集开始即冻结，绝不参与阈值选择。

## 5. 统一训练协议

### 5.1 共同设置

- 任务：单类目标检测，类别名统一为 `mikania`。
- 初始化：使用公开 COCO 预训练权重，不从零训练。
- 随机种子：筛选阶段使用 `20260804`；最终模型使用 `20260804`、`20260805`、`20260806`。
- 输入：主实验 640×640 letterbox；分辨率消融 960×960。
- 模型选择：只根据验证集；内部测试和时间外测试不参与早停、阈值或超参数选择。
- 精度：启用 AMP；每次运行记录实际软件版本、CUDA、GPU、耗时、显存峰值和最佳轮次。
- 检查点：按验证集 mAP@0.5:0.95 保存最佳权重，同时保存最后一轮权重。
- 停止：最大 200 epochs，验证集主指标连续 40 epochs 无改善则早停；烟雾测试只运行 10 epochs。
- batch：YOLO 默认每卡 16；其他模型通过梯度累积达到有效 batch 16。若显存变化，保持有效 batch 不变并记录。
- 测试时不使用随机增强；TTA 只能作为单独部署实验，不能混入主结果。

### 5.2 基础增强

所有 YOLO 基线共享同一套温和增强：水平翻转 0.5、旋转不超过 ±10°、平移不超过 10%、尺度 0.8–1.2、有限的亮度/饱和度变化；Mosaic 概率 0.5，并在最后 20 epochs 关闭。主基线不使用 MixUp、Copy-Paste 或会明显改变叶片形态的强增强。

跨模型比较时尽量复现同等几何和颜色增强；如果模型框架无法完全一致，必须保存实际配置并在论文中说明，而不是宣称训练条件完全相同。

### 5.3 阈值冻结

验证集包含确认负样本后，在验证集上选择一个部署置信度阈值：优先满足负样本图像误报率不高于 10%，再在可行阈值中选择最高召回率。若所有阈值都无法满足，则报告在正样本召回率 90% 条件下的最低误报率。阈值一经确定，对两个测试集保持不变。

## 6. 实验矩阵

### Phase 0：管线验证，不进入论文主表

| ID | 数据 | 模型 | 设置 | 通过条件 |
|---|---|---|---|---|
| S0 | D1 | YOLO26n | 640，10 epochs，seed 20260804 | 能读完数据、损失下降、验证集出现非零 AP、预测框坐标正常 |

S0 失败时只修复数据或训练管线，不进行模型调参。

### Phase 1：单种子基线筛选

| ID | 模型 | 输入 | 最大训练轮次 | 作用 |
|---|---|---:|---:|---|
| B0 | YOLO26n | 640 | 200 | 轻量实时下限与界面候选 |
| B1 | YOLO26s | 640 | 200 | 默认强基线 |
| B2 | Faster R-CNN ResNet50-FPN v2 | 短边 800、长边最多 1333 | 150 | 两阶段精度对照 |
| B3 | RT-DETRv2-R18 | 640 | 150 | NMS-free Transformer 对照 |
| B4 | YOLO26s | 960 | 200 | 分辨率消融，不算新模型贡献 |

筛选阶段全部只用 seed `20260804`。主模型选择规则：先比较验证集 mAP@0.5:0.95；差距不超过 1 个百分点时，依次选择验证集负样本 FPPI 更低、推理更快的模型。模型选择完成前不查看内部测试集和时间外测试集结果。

### Phase 2：困难负样本与方法消融

下列实验使用 Phase 1 选出的强基线，默认预计为 YOLO26s-640；若实际筛选结果不同，则替换为真实最强基线并记录原因。

| ID | 相对基线的变化 | 要回答的问题 |
|---|---|---|
| A0 | 只用正样本 D2 | 正样本基线的误报水平是多少 |
| A1 | 加入 D3 负样本，按自然比例混合 | 普通负样本是否已经有效 |
| A2 | 每个 batch 约 75% 正样本、25% 负样本；负样本按物种文件夹近似均匀采样 | 物种分层采样是否优于自然比例 |
| A3 | 在 A2 上用模型扫描负样本，按最大置信度和误报框数选出困难图，第二阶段提高其采样概率 | 错误驱动挖掘能否进一步降低误报 |
| A4 | 在 A3 上，从真值框和高分误报框提取区域特征，增加目标—困难背景的对比约束 | 区域级特征分离是否有独立贡献 |
| A5 | A3 使用 960 输入 | 高分辨率是否对困难场景有额外价值 |

其中 A3 是第一优先候选方法；A4 属于论文/专利增强模块，只有 A3 已稳定有效后才开发，避免在数据证据不足时过早修改网络结构。

### Phase 3：三种子确认与冻结测试

只对以下模型进行 3 个种子重跑：

1. 最强简单基线。
2. A3 困难负样本挖掘方法。
3. 若 A4 在筛选种子上有效，再加入 A4 完整方法。

三种子配置冻结后，依次评估内部测试集、困难负样本测试集和时间外测试集。不得依据测试结果回头更改训练配置；若确需更改，必须建立新实验版本并把原测试结果保留为探索性结果。

## 7. 指标与统计

### 7.1 定位能力

- COCO mAP@0.5:0.95（主要定位指标）
- AP50
- Precision、Recall、F1
- 每张正样本图至少检出一个正确目标的图像级召回率
- 按目标归一化面积分为 `<1%`、`1%–10%`、`≥10%` 三档的分层 AP/Recall

### 7.2 误报能力

- 负样本图像误报率：至少出现一个检测框的负样本图像比例
- FPPI：每张确认负样本图像的平均误报框数
- Recall@FPPI=0.1；数据不足时同时报告完整 Recall–FPPI 曲线
- 按三叶鬼针草、假臭草、火炭母、水蓼、大青叶及“其他”分别报告误报数，不把类别差异藏在总平均中

### 7.3 泛化与效率

- 内部测试与 2026 时间外测试的指标差值
- 单张延迟、吞吐量、模型参数量、权重体积、显存峰值
- 延迟必须在同一 GPU、batch=1、相同输入尺寸下测试；预热 50 次，正式计时至少 200 次，同时分别报告是否包含图像预处理和 NMS

### 7.4 统计规则

- 最终结果报告 3 个种子的均值 ± 标准差。
- 以 `split_unit_id` 为重采样单位做 2,000 次配对 bootstrap，报告方法相对基线的 95% 置信区间。
- 时间外测试只有 5 个划分单元，置信区间会很宽，应以描述性证据呈现。
- 主要确认性比较只设一个：A3 对最强简单基线。其他消融视为次要分析，避免从大量对比中挑选偶然最好结果。

## 8. 预设成功标准

### 工程原型目标

- 内部测试 AP50 ≥ 0.85；
- 内部测试 mAP@0.5:0.95 ≥ 0.55；
- 图像级召回率 ≥ 0.90；
- 确认负样本上的图像误报率 ≤ 0.20。

这些是项目目标，不是当前结果承诺。如果达不到，优先做标签和错误分析，而不是无限增加模型规模。

### 论文方法成功标准

A3 相对最强简单基线至少满足以下一项，并且 3 个种子方向一致：

1. 在召回下降不超过 2 个百分点时，负样本 FPPI 相对下降至少 30%；或
2. Recall@FPPI=0.1 提升至少 3 个百分点，且配对 bootstrap 的 95% 置信区间不跨 0。

### 分辨率停止规则

若 960 相比 640 的 mAP@0.5:0.95 提升不足 1 个百分点且延迟增加超过 30%，后续全部固定 640，不继续 P2 或更大分辨率实验。只有错误分析证明确实集中在缩放后短边小于 32 像素的目标时，才重新考虑小目标结构。

### 方法停止规则

若 A1–A4 均不能稳定优于“更多经确认的数据 + 简单强基线”，停止堆叠模块，转向补采跨地点、非花期和近似种数据。负结果应保留并进入论文的误差分析。

## 10. 误差分析与界面输出

每个冻结模型自动生成以下材料：

1. TP、FP、FN 图片画廊，并保存图片名、模型、阈值和数据版本。
2. PR 曲线、F1–Confidence 曲线、Recall–FPPI 曲线。
3. 按设备、日期、目标面积、物种负样本和采集组的指标表。
4. 基线与候选方法的同图对照，可直接用于论文图和系统展示。
5. 置信度低或不同模型结论不一致的复核队列，用于下一轮主动学习。

最终界面首先实现单图和批量识别、阈值调节、框与置信度显示、处理耗时、结果导出；无人机覆盖面积页等有分割标签后再开发。

## 11. 论文与专利证据链

### 论文主线

建议题目方向：**面向复杂混生植被的薇甘菊困难负样本目标检测方法**。

论文贡献必须由实验支持，预期证据链为：

1. 建立采集组和近重复隔离的数据协议，避免随机划分造成的虚高结果。
2. 建立包含相似植物的误报评估协议，而不只在全为正样本的图片上报告 mAP。
3. 证明物种分层困难负样本挖掘在固定召回条件下降低 FPPI。
4. 给出时间迁移、错误类型和部署效率分析。

### 专利候选

候选技术组合为：物种分层负样本池构建 → 基线扫描 → 高风险误报区域排序 → 困难区域重采样/对比约束 → 不确定样本复核回流。专利不能只写“用 YOLO 检测薇甘菊”；申请前需要进一步做权利要求级现有技术检索，并在论文公开技术细节之前确定申请顺序。

## 12. 执行顺序

1. 完成 16 个超大框、12 张缺标签图和 123 张负样本候选的质控。
2. 冻结 D2/D3 数据版本及 manifest 哈希。
3. 在服务器 GPU 0 运行 S0；通过后再并行 B0–B4。
4. 用验证集选择强基线，完成 A0–A3；A3 有效后再决定是否开发 A4。
5. 对最终候选运行 3 个种子，冻结阈值后只评估一次测试集。
6. 生成统计、图表和误差画廊，再决定专利实施例和论文主张。

## 13. 实现依据

- YOLO26 的自定义数据训练、训练参数和模型接口以 [Ultralytics 官方训练文档](https://docs.ultralytics.com/modes/train) 与 [YOLO26 官方模型页](https://docs.ultralytics.com/models/yolo26) 为准。
- Faster R-CNN 基线使用 [Torchvision 官方模型接口](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.detection.fasterrcnn_resnet50_fpn_v2.html)。
- RT-DETRv2 的输入和检测头以 [Hugging Face Transformers 官方文档](https://huggingface.co/docs/transformers/model_doc/rt_detr_v2) 为准；该官方说明推荐以 640×640 作为标准输入。
